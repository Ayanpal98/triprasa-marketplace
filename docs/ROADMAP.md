# Triprasa Roadmap

This roadmap describes intended work, not completed capabilities or committed launch dates.

## Phase 1 — Quick-commerce-inspired frontend
- [x] Responsive Tripura-rooted storefront concept
- [x] Prominent search and category shortcuts
- [x] Category filtering, name sorting and local demo basket
- [x] Browser-only seller-interest preview
- [x] Clear disclosure for sample catalogue and illustrative imagery
- [ ] Cross-browser and keyboard accessibility pass
- [ ] Real-device review at mobile, tablet and desktop breakpoints

## Phase 2 — Validate local commerce operations
- [ ] Interview prospective customers and local sellers
- [ ] Confirm the initial categories and launch geography
- [ ] Map seller inventory update and order acceptance workflows
- [ ] Validate packing, dispatch, delivery cost and rider/partner capacity
- [ ] Define serviceable areas and evidence-based delivery windows
- [ ] Validate cancellation, returns, refunds and customer support
- [ ] Define seller fees, delivery charges and seller net margins

## Phase 3 — Functional marketplace MVP
- [ ] Choose architecture after requirements and capacity are validated
- [ ] Design database, roles and access-control model
- [ ] Secure customer, seller and admin authentication
- [ ] Seller onboarding, document review and listing moderation
- [ ] Product catalogue with variants, units, prices and inventory
- [ ] Location/serviceability checks and delivery fee calculation
- [ ] Cart, checkout, payment, order lifecycle and refunds
- [ ] Seller order console and admin operations dashboard
- [ ] Notifications, audit logs, privacy and security controls

## Phase 4 — Controlled Tripura pilot
- [ ] Recruit a small, consented seller cohort
- [ ] Train sellers and test assisted onboarding
- [ ] Test end-to-end orders and fulfilment with real cost data
- [ ] Track order accuracy, delivery performance, cancellations, returns, repeat purchases and seller net earnings
- [ ] Review measured results before expansion

## Phase 5 — Northeast expansion
- [ ] Add new districts and towns only after service coverage is proven
- [ ] Expand categories and seller support workflows
- [ ] National shipping readiness for products that can be shipped reliably
- [ ] Multilingual support and additional regional discovery
- [ ] Evaluate live commerce and creator-led discovery when operationally ready

## Release gate
Do not launch live transactions or advertise rapid delivery until seller consent, accurate listings, inventory, serviceability, realistic delivery capacity, privacy, legal/compliance, payment, fulfilment, customer support, refund and security workflows have been tested.
