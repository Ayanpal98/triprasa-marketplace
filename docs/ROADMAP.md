# Triprasa Roadmap

This roadmap describes intended work, not completed capabilities or committed launch dates.

## Phase 0 — operating model and launch scope
- [x] Hybrid multi-vendor marketplace selected.
- [x] Local delivery partner model selected.
- [x] Agartala first selected as launch-planning geography; exact service localities remain TBD.
- [x] Responsive web + PWA first selected.
- [ ] Confirm launch categories and seller eligibility/verification.
- [ ] Validate seller stock, preparation and order acceptance processes.
- [ ] Define delivery partner onboarding, service zones, fees and failed-delivery workflow.
- [ ] Define platform fees, tax treatment, settlements, returns, refunds and customer support.

## Phase 1 — frontend and backend foundation
- [x] Responsive Tripura-rooted storefront concept and local demo basket.
- [x] PWA manifest, branded app icon and conservative offline app-shell service worker.
- [x] Documented proposed hybrid commerce architecture and pre-connection security review.
- [ ] Validate installability and offline fallback on real Android/desktop devices.
- [ ] Complete cross-browser, keyboard accessibility and responsive testing.
- [ ] Design new hybrid schema and role-specific RLS policies.
- [ ] Select a dedicated non-production Supabase project after explicit confirmation.
- [ ] Test migrations and role isolation before production review.

## Phase 2 — seller and catalogue operations
- [ ] Seller applications and verification workflow.
- [ ] Seller workspace, seller memberships and pickup locations.
- [ ] Product listings, variants, units, media moderation and stock management.
- [ ] Admin listing review and audit history.

## Phase 3 — multi-vendor commerce
- [ ] Server-owned cart and price validation.
- [ ] Parent order and seller fulfilment orders.
- [ ] Atomic stock reservation and order state transitions.
- [ ] Payment provider sandbox, signed webhooks and reconciliation.
- [ ] Cancellation, partial rejection, refunds and returns.

## Phase 4 — local delivery partner workflow
- [ ] Partner onboarding and verification.
- [ ] Service-area eligibility and manual dispatch.
- [ ] Assigned-job mobile workflow, pickup, delivery proof and exception handling.
- [ ] Delivery partner settlement and dispute handling.

## Phase 5 — controlled Agartala pilot
- [ ] Recruit consenting sellers and verify real product listings/photos.
- [ ] Test end-to-end orders, delivery cost, support, returns and payouts.
- [ ] Measure order accuracy, fulfilment performance, cancellations, returns and seller net earnings.
- [ ] Expand only after operational evidence supports it.

## Phase 6 — Tripura and Northeast expansion
- [ ] Add localities only after service coverage is proven.
- [ ] Expand categories, languages and seller support.
- [ ] Evaluate national shipping, creator-led discovery and live commerce when operationally ready.

## Release gate
Do not launch live transactions or advertise rapid delivery until seller consent, accurate listings, inventory, serviceability, realistic partner capacity, privacy, legal/compliance, payment, fulfilment, customer support, refund and security workflows have been tested.
