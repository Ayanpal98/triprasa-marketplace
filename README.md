# Triprasa — Rooted in Tripura, open to the world

Triprasa is an early-stage, community-first marketplace concept intended to help Tripura's indigenous producers, local makers and small businesses present their work to wider audiences.

## Current status

**Frontend prototype with shared-backend scaffolding.** The repository includes a responsive storefront, illustrative product cards, client-side search and category filters, sorting, a local demo basket, and a local-only seller-interest flow. Supabase schema and adapter files are prepared but not connected.

- No live backend connection, shared accounts, live seller onboarding, real checkout, payments, shipping, or order processing. The Supabase schema is proposed and has not been applied.
- Product names, maker labels, descriptions and prices are illustrative placeholders, not verified listings or purchase offers.
- Maker-interest submissions currently remain in the visitor's browser; they are not sent to a server or visible to other devices.
- No real traction, seller count, partnerships, certifications or impact results are claimed.

## Run locally

Open `index.html` directly in a modern browser, or serve the repository using any static file server. There is no package manager or build step.

## Product principles

1. Maker-first and community-informed.
2. Consent and attribution before publishing cultural stories, designs or personal details.
3. Transparent pricing, fees, fulfilment and seller economics.
4. Accessible, mobile-first discovery.
5. Validate locally before expanding to national or international fulfilment.
6. Make no unsupported claims about seller verification, provenance, impact or traction.

## Suggested next steps

1. Review the storefront and complete a browser-based accessibility/responsive pass.
2. Conduct consent-based interviews with prospective sellers and community stakeholders.
3. Validate categories, production capacity, packaging, shipping costs, returns and net seller margins.
4. Define the data model, privacy requirements and seller/admin workflows before selecting backend architecture.
5. Run a small, measured pilot only when consent, accurate listings, payments, fulfilment, customer support and compliance are ready.
